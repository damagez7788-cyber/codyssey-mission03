# 강준권의 Mini NPU Simulator

제출자: **강준권**

코디세이 미션 3 ‘AI가 계산하는 방식을 흉내 내는 작은 계산기 만들기’ 프로젝트입니다.
그림을 숫자 배열로 보고, 같은 위치를 곱해서 더하는 MAC 연산을 반복문으로 구현했습니다.
실제 NPU 하드웨어나 AI 학습 모델이 아니라 그 계산 원리를 설명하는 Python 콘솔 시뮬레이터입니다.

## 1. 실행 방법

Python 3.8 이상, 표준 라이브러리만 사용합니다. 실제 검증 환경은 WSL Ubuntu / Python 3.14.4입니다.
VS Code에서 이 폴더를 열고 Ubuntu 터미널에서 실행합니다.

```bash
python3 main.py
```

`python3`로 시작 파일 `main.py`를 실행합니다. 메뉴 1은 3×3 직접 입력, 메뉴 2는 공식 JSON 분석입니다.
각 줄에 숫자 3개를 공백으로 구분해 입력합니다. 행을 세 번 입력하면 3×3 한 개가 완성됩니다.
필터 A, 필터 B, 패턴 순서로 총 9행을 입력합니다. 열 수나 숫자가 잘못되면 같은 행을 다시 받습니다.
입력 중 Ctrl+C 또는 EOF이면 안내 후 종료하며 공식 JSON을 수정하지 않습니다.

```bash
python3 main.py --data data.json --repeats 100
```

위 명령은 메뉴 없이 `--data` 뒤 파일을 분석하고, `--repeats 100`으로 각 크기의 MAC을 100회 측정합니다.
반복 수는 최소 10회이며 기본값도 100회입니다. Windows에 Python이 있으면 `python` 명령으로 실행 가능합니다.
메뉴 2는 프로젝트 루트 `data.json`을 사용합니다. `--data`의 상대 경로는 터미널의 현재 폴더 기준입니다.

3×3 시연 입력 예시:

```text
필터 A          필터 B          패턴
0 1 0           1 0 1           1 0 1
1 1 1           0 1 0           0 1 0
0 1 0           1 0 1           1 0 1
```

실제 입력은 열을 나눠 한꺼번에 붙이지 않고, A의 3행 → B의 3행 → 패턴 3행 순서입니다.
예상 결과는 A=1, B=5, 판정 B입니다. [실제 입력 및 출력](evidence/03_interactive.txt)에서 재입력까지 확인했습니다.

## 2. 구현 요약

| 파일 | 역할 |
|---|---|
| main.py | 모드 선택, 3×3 행 입력, 오류 안내 |
| matrix.py | 정사각 배열 크기·수치 검사, 위치별 읽기/쓰기 |
| npu.py | 반복문 MAC, 라벨 정규화, epsilon 판정, 시간 측정 |
| analysis.py | JSON 검증, 케이스별 결과·합계·성능 표 |
| data.json | 코디세이에서 받은 공식 원본 데이터 |
| tests/ | 계산·입력·오류 전파를 검사하는 표준 unittest |
| evidence/ | 명령·실제 입력/출력·검증 결과·독립 계산 |

MAC은 `for 행 → for 열 → 입력값 × 필터값 누적`으로 계산합니다. 외부 배열 라이브러리는 없습니다.
행렬은 정사각이어야 하며 크기가 다르거나 숫자가 아닌 값·NaN·무한대는 오류로 안내합니다.
`patterns`의 `size_N_idx`에서 N을 읽어 `filters.size_N`을 선택합니다.
expected의 `+`와 필터 키 `cross`는 `Cross`, `x`는 `X`로 통일한 뒤 비교합니다.
`abs(A-B) < 1e-9`이면 `UNDECIDED`, 그 외에는 점수가 큰 필터로 판정합니다.
허용오차는 절대 오차 기준이며, 정확히 1e-9인 차이는 동점에 포함하지 않습니다.

## 3. 실제 결과 리포트

검증일: 2026-11-05. 공식 데이터 6개 중 **3 PASS / 3 FAIL**입니다.
FAIL은 분석 대상 패턴의 expected와 판정이 다르다는 뜻이며, 프로그램 중단을 뜻하지 않습니다.

| 케이스 | Cross 점수(수학적 값) | X 점수(수학적 값) | 판정 | expected | 결과 |
|---|---:|---:|---|---|---|
| size_5_1 | 0.90 | 0.90 | UNDECIDED | X | FAIL |
| size_5_2 | 8.90 | 0.10 | Cross | Cross | PASS |
| size_13_1 | 0.30 | 14.70 | X | X | PASS |
| size_13_2 | 7.50 | 7.50 | UNDECIDED | Cross | FAIL |
| size_25_1 | 4.90 | 4.90 | UNDECIDED | X | FAIL |
| size_25_2 | 52.90 | 0.10 | Cross | Cross | PASS |

1. 공식 JSON의 라벨 표기가 다르므로 입력을 Cross/X로 정규화했습니다.
2. 정규화가 없으면 `+`와 `Cross`처럼 의미가 같은 값도 다르다고 비교할 수 있습니다.
3. 원본의 필터 가중치는 단순한 0/1 그림과 다르므로, 결과를 예시의 5점/1점으로 강제하지 않습니다.
4. size_5_1의 수학적 점수는 0.9 대 0.9로 동점입니다.
5. size_13_2의 수학적 점수도 7.5 대 7.5로 동점입니다.
6. size_25_1의 수학적 점수도 4.9 대 4.9로 동점입니다.
7. float 누적에서는 0.90000000000000002와 0.89999999999999991 같은 작은 차이가 생깁니다.
8. 이 차이를 그대로 승패로 사용하지 않고 epsilon=1e-9 안의 차이는 판정 불가로 처리했습니다.
9. 동점 세 건의 expected는 X 또는 Cross이므로 UNDECIDED와 일치하지 않아 FAIL입니다.
10. 이 FAIL을 없애려고 expected나 필터를 바꾸지 않았습니다. 동점 시 특정 클래스를 고르는 규칙도 추가하지 않았습니다.
11. 별도의 Decimal 십진수 계산으로 세 건 모두 정확한 동점인 것을 독립 확인했습니다.
12. 따라서 이번 세 실패는 누락된 라벨 정규화나 행렬 크기 오류가 아니라, 데이터의 동점과 정해진 비교 정책의 결과입니다.
13. 별도 임시 데이터에 크기 오류를 넣었을 때 해당 케이스만 추가 FAIL이 되고 나머지는 계속 처리됐습니다.
14. JSON 전체가 없거나 손상된 경우는 파일 오류로 안내합니다. 케이스 내부 오류와 파일 전체 오류를 구분합니다.
15. 프로그램은 분석을 끝내면 종료 코드 0을 반환합니다. 패턴 FAIL 수는 별도로 출력합니다. 파일을 못 읽으면 종료 코드 1입니다.

### 시간 복잡도와 실제 성능

아래는 검증 요약 파일에 저장된 실제 측정입니다. MAC 한 번을 100회 반복해 평균을 냈으며, 파일 읽기·입력·결과 출력은 측정 구간에 넣지 않았습니다.

| 크기 | 평균 시간(ms) | MAC 횟수 N² |
|---|---:|---:|
| 3×3 | 0.010906 | 9 |
| 5×5 | 0.008033 | 25 |
| 13×13 | 0.050102 | 169 |
| 25×25 | 0.263014 | 625 |

행 반복 N회와 각 행의 열 반복 N회를 곱해 한 필터에 N²번의 MAC을 합니다. 따라서 시간 복잡도는 O(N²)입니다.
두 필터 비교는 2N²이지만 상수 2를 제외하면 역시 O(N²)입니다. 배열 저장 공간도 O(N²)입니다.
이 표의 횟수는 곱하고 더하는 한 쌍(MAC) 기준입니다. 곱셈과 덧셈을 별개 산술 연산으로 세면 각각 N²회입니다.
작은 입력의 시간은 OS 스케줄링·Python 호출 비용·부하에 영향을 받아 항상 크기 순으로 증가하지는 않습니다.
이번에도 3×3이 5×5보다 느린 측정이 있었습니다. 이 값을 고치거나 시간만으로 복잡도를 증명하지 않았습니다.
복잡도 근거는 반복문 구조와 N² 횟수이며, 시간 표는 이 환경에서의 관찰입니다. 실제 NPU 성능이나 병렬 가속률을 주장하지 않습니다.

`unittest`로 `tests` 폴더의 검사들을 찾아 실행합니다. `-v`는 각 검사 이름과 결과를 자세히 보여줍니다.
